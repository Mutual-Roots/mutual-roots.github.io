“fordiverse-rclone” is the name of an OAuth client in a Google Cloud project owned by Simon Moritz Reichard. It is used exclusively by Simon Moritz Reichard with the open-source tool rclone to access their own Google Drive account. It is not a public service: there are no other users, registration or download.

  • Google data accessed: The scope https://www.googleapis.com/auth/drive allows access to files and their metadata (names, folders, sizes, timestamps and checksums) in Simon Moritz Reichard's own Google Drive.
  • Use: Only to upload, download, synchronize and back up the operator's own files (such as model files and backups) between their own devices and their own Google Drive.
  • Storage: The OAuth token is held in the local rclone configuration on the operator’s own computers, with a second copy in the operator’s own password vault. Files from Google Drive are stored only on Simon Moritz Reichard's own devices. This website does not store or process Google data.

  • No AI training: The data are not used to train AI or ML models.
  • Limited Use: fordiverse-rclone's use and transfer to other apps of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements.
  • Revocation: Access can be revoked at any time in the Google account at https://myaccount.google.com/permissions; local tokens are then deleted too.
  • Data subjects: Only Simon Moritz Reichard's own data are processed.

Fordiverse Mail (Private Google OAuth mail access)

Operator and contact: Simon Moritz Reichard, mutual.ford.perfect@gmail.com. This private service is for the operator and personally known account holders who authorize access to their own Gmail accounts. There is no public self-registration.

This app belongs to the Google Cloud project “Google MI Auth Gate”. The existing Google consent dialog may still display “extern” as its app name. This information page does not confirm that the Google branding has already been changed or verified.

  • Google data accessed: Folders and message lists, message bodies and headers, and attachments where applicable, from the Gmail accounts that have been authorized. The Google grant does not cover accounts with other mail providers.
  • Permission: https://mail.google.com/. This broad Gmail scope technically also permits sending and deleting messages. The current use described here is listing, reading and local mirroring; granting Google access is not a separate instruction to send or delete messages.
  • Purpose and current use: Fordiverse Mail provides account-scoped API/MCP interfaces and Pimalaya for listing and reading authorized Gmail mailboxes. Mail copies stay locally in the self-hosted Fordiverse installation; configured mirrors are stored with Mox and read in the Cypht reader.
  • Credentials: OAuth tokens are held in the existing self-hosted OpenBao secret store and the designated protected service runtimes. They are not stored on this public website.
  • Mail copies and retention: Mail copies, headers and attachments are retained locally in the self-hosted installation for the mailbox management, mirroring and recovery requested by the account holder. They remain available for as long as needed for those purposes or as long as the account holder requests retention. Deletion and the end of retention can be requested from the operator. Temporary fetch files and operational backups must be considered separately. This public website stores no mail content.
  • Mail data protection: Mail is retrieved over encrypted IMAPS connections. The mail integration checks the enabled account and the agents authorized for it. Temporary original-message files and local import files are stored under designated service accounts with restrictive directory and file permissions. OAuth tokens are held in the designated protected secret store. These statements describe the access controls in use and do not promise full-disk encryption.
  • API/MCP clients and data recipients: Agents are independent API/MCP clients selected and authorized by the account holder. The mail function does not require an embedded AI model. Users can provide their own provider credentials for their clients (BYOK: Bring Your Own Key). When a user instructs a client to send specified mail data to another service, the user also instructs that recipient to process those data for the stated purpose under that service’s applicable data-protection and retention terms. The recipient and purpose must be known and authorized before transmission. A Google grant or a personal API key does not replace that instruction.
  • Use restrictions: Fordiverse does not use Google Workspace data to develop, improve or train non-personalized AI or ML models. These data are not used for advertising or data sales either. Transfer to connected clients and other services is permitted only for the requested, user-facing mail functions; recipients must observe the same Limited Use restrictions. Choosing an external client or BYOK credentials does not remove Fordiverse’s own data-protection and security obligations.
  • Limited Use: Fordiverse Mail's use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements.
  • Revocation: Google access can be revoked at any time in the Google account. This ends future access through that grant; it does not automatically delete mail copies that have already been stored. Google account permissions
  • Deletion: Account holders can request deletion of stored mail copies and credentials using the contact below. The operator clarifies the scope of active copies, temporary fetch files and existing backups. Recovery copies serve only the requested backup purpose; their continued retention follows the backup arrangement requested by the account holder. Deleting an active mail copy does not immediately remove existing backups. Revoking Google access and deleting data already stored are separate steps.
